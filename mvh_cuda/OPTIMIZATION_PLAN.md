# 分阶段优化记录

用户给出的历史 profiling 数值用于确定调查顺序，不作为当前版本实测基线。
242 秒打包已包含 99 秒 spectra_and_top，不能相加；其余计时也应先核对嵌套关系。
当前分支只保留粗粒度运行计时，细粒度归因按 PROFILING.md 在 profiling 分支进行。

| 优先级 | 可行性与实施边界 | 验证要求 |
|---|---|---|
| 1 序列 ID 与打包 | 当前已使用 PMR arena。本轮改为连续槽位、条目和自有字节存储，消除节点式哈希访问；唯一字符串仍复制一次，字节区增长仍可能搬迁。容量跨批复用见第 2 步。 | ID 首次出现顺序、完整字符串比较、结果恢复期间所有权；真实数据同后端 PSM 一致性。 |
| 2 Top 跨批复用 | 可行，但稳定 ID 应有数据集级生命周期和内存上界，先确认 merge/top 对 ID 的全部依赖。GPU Top 常驻需保持恢复顺序。 | 多批次重复序列、同分排序、Top 替换、数据集重置。 |
| 3 内存生命周期 | 可分步复用批次向量，再评估肽对象池。不能在结果恢复或异步操作结束前复用对象。 | 峰值 RSS、完整进程耗时及结果一致性。 |
| 4 肽生成 | 先区分酶切、修饰枚举、字符串与分配热点，再选择改动。 | 当前构建的 CPU profile；输出候选顺序和数量。 |
| 5 CPU–GPU 流水 | 有条件可行，先梳理 preparedPeptides、assignedBatch 和谱图等共享状态，明确双缓冲所有权；Top 合并须保持批次顺序。 | 并发正确性、峰值内存/显存、端到端吞吐。 |
| 6 理论离子复用 | 按实际肽/电荷组合或有界分块值得评估；须核对缓存键的评分配置和显存预算。 | 缓存/直接生成结果一致；命中率与新增索引成本。 |
| 7 GPU 工作区 | 可行；已有 host/device 谱图缓存，应先测 device 模式，再评估按容量增长的工作区。 | 显存峰值、关联阶段可用显存和总时间。 |
| 8 RT kernel | occupancy 本身不能确定瓶颈；先查寄存器、依赖、访存和遍历等待，再决定拆分。 | 实际 kernel 时间、评分语义及端到端收益。 |

## 第 1 步：连续序列 ID 表

使用至多 50% 装载的线性探测，保存 hash 和文本偏移；文本扩容不使条目失效。
不改变评分公式、候选遍历顺序、跨批 ID 规则或 GPU 接口。
新增差分测试覆盖空串、内嵌零字节、共同前缀、重复键、增长和探测回绕。

100 万合成键插入及 400 万重复查询，包含表创建和销毁，三轮平均
1.227 → 1.077 秒（减少 12.2%）；进程峰值 RSS 约减少 12.4%。
这是局部合成实验，不代表实际 141 秒阶段或全流程的加速比例。
实验源码、前后头文件和记录位于
`output/benchmarks/host_reuse/sequence_ids_20260929/`（本地输出，未纳入版本控制）。

主机契约测试（g++、本地 CUDA 13.3 nvcc）与 ASan/UBSan 检查通过；沙箱 ptrace 环境不支持 LeakSanitizer，
因此关闭了泄漏检测。当前缺少文档所述运行中的项目容器，完整 GPU CTest、
真实数据同后端 PSM 前后比较和性能测量仍待完成。


## 第 2 步：主机工作区与 ID 表容量复用

已实现：
- ID 表 reset 保留容量，清除旧键并从零重新编号。
- 评分输入、Top 打包/回传、事件与统计数组跨批复用。
- 预处理文本、规则、容量、长度和错误数组跨批复用。
- 去掉肽对象指针数组复制；偏移直接写入 PreparedPeptides，去掉偏移数组复制。
- 数据集重置及 MatchBackendScope 退出时释放缓存；未完成的准备/关联状态也清理。

正常/异常返回后，本批设备资源仍由局部 RAII 对象释放。工作区保留容量可能增加
后续阶段的 RSS 峰值，因此需要实测总时间和主机峰值；未声称本步减少内存或带来
确定的加速比例。ID 和 Top 内容仍按每批原流程构建，尚未实现第 2 优先级的稳定 ID
或 GPU Top 常驻。肽对象池留作下一个独立改动；其接入应在 database_search.cpp，
保持 original/ 源码契约，并显式复位 Peptide 全部字段及容器。

验证：ID 顺序/所有权/扩容/跨批重置测试与 ASan/UBSan 通过（关闭环境不支持的
LeakSanitizer）；新增分配计数测试确认预热后的同等/更小批次不发生堆分配。
原始源码身份检查、CPU 基线与转换范围检查通过。
本地 CUDA 13.3 构建尝试受 CUB API 兼容性阻碍，GPU 访问也被操作系统阻止；
CUDA/RT 集成测试、真实 PSM 对照和端到端性能仍未验证。
